De cero a tu primer git push

Instala Git, crea tu cuenta de GitHub, conéctala con Visual Studio Code y aprende los comandos que usarás todos los días: clonar, confirmar cambios (commit), subir, bajar y trabajar con ramas.

      1
      Conceptos

      Qué son Git y GitHub (y por qué no son lo mismo)

      Antes de instalar nada, conviene tener claro el mapa mental. Cinco minutos aquí te ahorran horas de confusión después.

      Git es un programa que se instala en tu computadora. Guarda el historial de cambios de una carpeta: cada vez que "confirmas" (haces un commit), Git toma una foto del proyecto que puedes recuperar después.

      GitHub es una página web (github.com) donde guardas una copia de ese historial en la nube, para respaldarlo, compartirlo y trabajar en equipo.

      Visual Studio Code es el editor de código donde escribes tu proyecto. Trae Git integrado, así que puedes hacer casi todo con botones o con su terminal.

      Idea claveUn commit vive primero solo en tu computadora. Hasta que no haces push, GitHub no lo ve. Esto es lo que más confunde al principio.
      2
      Instalación

      Instalar Git en tu computadora

      Elige tu sistema operativo. Si tienes dudas en alguna pantalla del instalador, deja la opción que viene marcada.

      1. Entra a git-scm.com/downloads/win y descarga el instalador de 64 bits.
      2. Ábrelo y avanza con Next. Presta atención solo a estas pantallas:
      3. Choosing the default editor: elige "Use Visual Studio Code as Git's default editor".
      4. Adjusting the name of the initial branch: marca "Override the default branch name" y escribe main.
      5. Adjusting your PATH: deja "Git from the command line and also from 3rd-party software" (recomendado).
      6. Credential helper: deja "Git Credential Manager". Es lo que abrirá el navegador para iniciar sesión en GitHub la primera vez.
      7. Termina con Install y luego Finish.
      ExtraEl instalador también trae Git Bash, una terminal tipo Linux. Puedes usarla, pero en esta guía usaremos la terminal integrada de VS Code.

      Abre la app Terminal (búscala con ⌘ + Espacio) y usa una de estas dos opciones:

      Opción A · herramientas de Apple
      xcode-select --install
      Opción B · con Homebrew (si ya lo tienes)
      brew install git

      Abre una terminal y ejecuta el comando de tu distribución:

      Ubuntu / Debian / Mint
      sudo apt update
sudo apt install git
      Fedora
      sudo dnf install git

      Comprueba que quedó instalado

      Abre una terminal nueva (en Windows: busca "Git Bash" o "PowerShell") y escribe:

      terminal
      git --version

      Si ves algo como git version 2.51.0, ¡listo! El número exacto puede ser otro; lo importante es que no diga "comando no encontrado".

      3
      Cuenta

      Crear tu cuenta en GitHub

      Tu perfil de GitHub será tu portafolio como programador. Elige un nombre de usuario que te dé gusto mostrar.

      1. Ve a github.com/signup.
      2. Escribe tu correo, una contraseña segura y un nombre de usuario (por ejemplo ana-torres-dev). Evita apodos que no usarías en una entrevista de trabajo.
      3. Resuelve la verificación y revisa tu correo: GitHub te enviará un código para confirmar la cuenta.
      4. Activa la verificación en dos pasos (2FA) en Settings → Password and authentication. GitHub la exige para poder contribuir en código.
      5. Opcional pero útil: agrega foto y una breve biografía en tu perfil.
      EstudiantesCon tu correo institucional puedes solicitar el GitHub Student Developer Pack, que incluye GitHub Copilot y otras herramientas gratis mientras estudias.
      Anota estoRecuerda el correo con el que te registraste: lo usarás en el paso 5 para configurar Git.
      4
      Editor

      Instalar Visual Studio Code

      VS Code detecta Git automáticamente si ya lo instalaste en el paso 2.

      1. Descárgalo desde code.visualstudio.com.
      2. En Windows, durante la instalación marca estas casillas: "Agregar la acción 'Abrir con Code' al menú contextual" (para archivos y carpetas) y "Agregar a PATH".
      3. Abre VS Code. Si lo quieres en español: Ctrl + Shift + X → busca Spanish Language Pack → Instalar → reinicia.

      Las partes de VS Code que usarás

      ExploradorCtrl+Shift+E · tus archivos y carpetas.
      Control de código fuenteCtrl+Shift+G · el panel de Git: cambios, commits, sincronizar.
      Terminal integradaCtrl+ñ o Ctrl+` · para escribir comandos.
      Paleta de comandosCtrl+Shift+P · busca cualquier acción, por ejemplo "Git: Clone".

      En macOS cambia Ctrl por ⌘.

      5
      Configuración · una sola vez

      Decirle a Git quién eres

      Cada commit lleva tu nombre y correo. Configúralos una vez y Git los usará siempre en esta computadora.

      En VS Code abre la terminal (Ctrl + ñ) y escribe, cambiando los datos por los tuyos:

      terminal · configuración global
      git config --global user.name "Ana Torres"
git config --global user.email "ana@correo.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
      • user.name: tu nombre como quieres que aparezca en los commits.
      • user.email: el mismo correo de tu cuenta de GitHub, así tus commits se vinculan a tu perfil.
      • init.defaultBranch main: los repositorios nuevos empiezan en la rama main, igual que en GitHub.
      • core.editor: cuando Git necesite que escribas un texto largo, abrirá VS Code.

      Para revisar lo que configuraste:

      terminal
      git config --global --list
      ¿Privacidad?Si no quieres que tu correo sea público, en GitHub ve a Settings → Emails, activa "Keep my email addresses private" y usa el correo tipo 12345+usuario@users.noreply.github.com que te muestra ahí.
      6
      Vinculación

      Vincular tu cuenta de GitHub con VS Code

      Así VS Code puede clonar tus repositorios, subir cambios y publicar proyectos nuevos sin pedirte la contraseña cada vez.

      Opción recomendada: desde VS Code

      1. Haz clic en el ícono de Cuentas (la silueta de persona abajo a la izquierda, en la barra lateral).
      2. Elige "Iniciar sesión con GitHub…" (o "Sign in with GitHub"). Si no aparece, ve primero al panel de control de código fuente y elige Clonar repositorio → Clonar desde GitHub: VS Code te pedirá iniciar sesión.
      3. Aparece un aviso: "La extensión GitHub quiere iniciar sesión…". Pulsa Permitir.
      4. Se abre el navegador. Inicia sesión en GitHub y pulsa Authorize Visual-Studio-Code.
      5. El navegador pedirá volver a VS Code: acepta Abrir Visual Studio Code. Ya verás tu usuario en el menú de Cuentas.
      Al primer pushLa primera vez que subas cambios, puede abrirse otra ventana de Git Credential Manager pidiendo iniciar sesión. Elige Sign in with your browser y autoriza. Solo pasa una vez.
      Alternativa: iniciar sesión con GitHub CLI (gh)

      GitHub CLI es una herramienta oficial para la terminal. Instálala desde cli.github.com y luego:

      terminal
      gh auth login

      Responde: GitHub.com → HTTPS → Yes (authenticate Git) → Login with a web browser. Copia el código de 8 caracteres que te muestra y pégalo en el navegador.

      Alternativa avanzada: llaves SSH

      Útil si trabajas en laboratorios o servidores. Genera una llave (presiona Enter en todas las preguntas):

      terminal
      ssh-keygen -t ed25519 -C "ana@correo.com"
cat ~/.ssh/id_ed25519.pub

      Copia el texto que empieza con ssh-ed25519, ve a GitHub → Settings → SSH and GPG keys → New SSH key, pégalo y guarda. Comprueba con:

      terminal
      ssh -T git@github.com

      Con SSH, clona usando la URL que empieza con git@github.com: en vez de https://.

      7
      git clone

      Descargar un repositorio (clonar)

      "Clonar" es descargar un proyecto de GitHub con todo su historial, ya conectado para poder subir y bajar cambios. Es distinto a descargar un ZIP.

      Primero, copia la URL del repositorio

      En la página del repositorio en GitHub, pulsa el botón verde <> Code, pestaña HTTPS, y copia la dirección. Se ve así:

      URL de ejemplo
      https://github.com/usuario/nombre-del-repo.git
      1. Abre VS Code sin ninguna carpeta (Archivo → Cerrar carpeta).
      2. Pulsa Ctrl+Shift+P y escribe Git: Clone.
      3. Pega la URL (o elige Clonar desde GitHub para ver tu lista de repositorios).
      4. Elige la carpeta donde se guardará, por ejemplo Documentos/proyectos.
      5. Cuando termine, pulsa Abrir. Ya estás dentro del proyecto.
      terminal
      # 1. Ve a la carpeta donde guardas tus proyectos
cd Documents
# 2. Clona el repositorio
git clone https://github.com/usuario/nombre-del-repo.git
# 3. Entra a la carpeta y ábrela en VS Code
cd nombre-del-repo
code .

      code . abre VS Code en la carpeta actual (el punto significa "aquí").

      CuidadoNo clones un repositorio dentro de otro repositorio. Guarda cada proyecto en su propia carpeta, dentro de una carpeta general como proyectos.
      8
      git add · git commit

      Guardar cambios: status, add y commit

      Este es el ciclo que repetirás cientos de veces: cambiar archivos, revisar, preparar y confirmar.

      terminal
      # ¿Qué cambió? (úsalo todo el tiempo)
git status

# Ver exactamente qué líneas cambiaron
git diff

# Preparar un archivo concreto…
git add index.html
# …o todos los cambios de la carpeta
git add .

# Confirmar con un mensaje que explique el cambio
git commit -m "Agrega formulario de contacto"
      1. Abre el panel Control de código fuente (Ctrl+Shift+G). Verás la lista de archivos modificados con letras: M = modificado, U = nuevo (sin seguimiento), D = eliminado.
      2. Haz clic en un archivo para ver el antes y el después lado a lado.
      3. Pulsa el + junto a cada archivo (o junto a "Cambios" para todos). Pasan a Cambios almacenados provisionalmente (staging).
      4. Escribe el mensaje en el cuadro de texto de arriba.
      5. Pulsa ✓ Confirmar (Commit) o Ctrl+Enter.

      Cómo escribir un buen mensaje de commit

      EvitaMejor
      cambiosCorrige el cálculo del promedio en notas.py
      asdfAgrega estilos al menú de navegación
      ya quedó final finalElimina archivos de prueba que no se usan
      • Empieza con un verbo en presente: Agrega, Corrige, Elimina, Actualiza, Mejora.
      • Un commit = un cambio con sentido. Es mejor hacer varios commits pequeños que uno gigante al final del día.
      9
      git push · git pull

      Subir y bajar cambios: push y pull

      Tus commits ya están guardados en tu PC. Ahora hay que sincronizarlos con GitHub.

      terminal
      # Traer los cambios nuevos de GitHub (hazlo antes de empezar a trabajar)
git pull

# Subir tus commits a GitHub
git push

      En VS Code, el botón azul Sincronizar cambios del panel de Git (o las flechas ↓↑ en la barra inferior) hace pull y después push de una vez. El número junto a las flechas indica cuántos commits faltan por bajar (↓) o subir (↑).

      Hábito de oropull al empezar, commit seguido mientras trabajas, push al terminar. Si trabajas en equipo, este hábito evita la mayoría de los conflictos.

      Después del push, actualiza la página del repositorio en GitHub: verás tu mensaje de commit junto a los archivos que cambiaste.

      10
      git init · git remote

      Crear y publicar tu propio repositorio

      ¿Tienes una carpeta con un proyecto en tu PC que aún no está en GitHub? Hay dos caminos.

      1. Abre la carpeta del proyecto en VS Code (Archivo → Abrir carpeta).
      2. Ve al panel de Git (Ctrl+Shift+G) y pulsa Publicar en GitHub.
      3. Elige repositorio público (visible para todos, ideal para portafolio) o privado.
      4. Selecciona qué archivos incluir y confirma. VS Code crea el repositorio en GitHub, hace el primer commit y lo sube.

      Primero crea un repositorio vacío en GitHub: botón + (arriba a la derecha) → New repository → ponle nombre → no marques "Add a README" → Create repository. Luego, dentro de tu carpeta:

      terminal
      git init
git add .
git commit -m "Primer commit"
git branch -M main
git remote add origin https://github.com/tu-usuario/mi-proyecto.git
git push -u origin main
      • git init convierte la carpeta en repositorio (crea una carpeta oculta .git).
      • git remote add origin … le dice a Git dónde está tu repositorio en GitHub. "origin" es el apodo de esa dirección.
      • -u recuerda la conexión: desde ahora basta con git push.
      READMEAgrega un archivo README.md que explique qué hace tu proyecto y cómo ejecutarlo. Es lo primero que ve quien visita tu repositorio.
      11
      .gitignore

      Ignorar archivos con .gitignore

      Hay archivos que nunca deben subirse: contraseñas, dependencias descargadas o archivos que genera tu computadora.

      Crea en la raíz del proyecto un archivo llamado exactamente .gitignore y escribe un patrón por línea:

      .gitignore
      # Dependencias
node_modules/
venv/
__pycache__/

# Secretos y configuración local
.env

# Archivos del sistema
.DS_Store
Thumbs.db

# Resultados de compilación
dist/
*.log
      ImportanteSi subiste por error una contraseña o clave, cambiarla es obligatorio: borrar el archivo después no la quita del historial.

      GitHub tiene plantillas listas por lenguaje en github.com/github/gitignore.

      12
      git switch · git merge

      Trabajar con ramas

      Una rama es una línea de trabajo paralela. Te permite probar algo nuevo sin romper la versión que ya funciona en main.

      terminal
      # Ver ramas (la actual tiene un *)
git branch

# Crear una rama nueva y cambiarte a ella
git switch -c menu-nuevo

# …trabajas y haces commits como siempre…

# Subir la rama a GitHub la primera vez
git push -u origin menu-nuevo

# Volver a main y unir los cambios de la rama
git switch main
git merge menu-nuevo

# Borrar la rama cuando ya no la necesites
git branch -d menu-nuevo

      En VS Code, el nombre de la rama actual aparece en la esquina inferior izquierda. Haz clic ahí para cambiar de rama o crear una nueva.

      ¿checkout?En tutoriales antiguos verás git checkout -b rama. Hace lo mismo que git switch -c rama; switch es más nuevo y más fácil de recordar.
      13
      Pull request · fork

      Trabajo en equipo: pull requests y forks

      En proyectos reales nadie sube directo a main: se propone el cambio y otra persona lo revisa.

      Si eres colaborador del repositorio

      1. El dueño te agrega en Settings → Collaborators y aceptas la invitación que llega a tu correo.
      2. Creas una rama, haces commits y la subes con git push -u origin mi-rama.
      3. En GitHub aparece el botón Compare & pull request. Describe qué hiciste y pulsa Create pull request.
      4. Tus compañeros revisan, comentan y, cuando está aprobado, alguien pulsa Merge pull request.
      5. En tu PC vuelves a main y haces git pull para tener la versión actualizada.

      Si no tienes permiso (proyecto ajeno)

      Pulsa Fork en la página del repositorio. GitHub crea una copia en tu cuenta; clonas tu copia, haces tus cambios y abres un pull request hacia el repositorio original.

      Extensión útilInstala GitHub Pull Requests en VS Code para crear, revisar y comentar pull requests sin salir del editor.
      14
      Rescate

      Deshacer cosas y solucionar errores comunes

      Equivocarse es normal. Git casi siempre tiene una forma de volver atrás.

      Quiero…Comando
      Descartar los cambios de un archivo (sin commit todavía)git restore archivo.txt
      Sacar un archivo del staging (deshacer el add)git restore --staged archivo.txt
      Corregir el mensaje del último commit (si aún no hiciste push)git commit --amend -m "Mensaje nuevo"
      Deshacer el último commit pero conservar los cambiosgit reset --soft HEAD~1
      Revertir un commit que ya está en GitHubgit revert <hash>
      Ver el historial en una línea por commitgit log --oneline --graph
      ReglaSi el commit ya está en GitHub y otros lo descargaron, usa git revert (crea un commit nuevo que deshace el anterior). No reescribas historia compartida.

      Mensajes de error frecuentes

      Author identity unknown · Please tell me who you are

      No configuraste tu nombre y correo. Vuelve al paso 5 y ejecuta los dos comandos git config --global.

      fatal: not a git repository

      Estás en una carpeta que no es un repositorio. Revisa dónde estás con pwd y entra a la carpeta correcta con cd nombre-del-repo, o créalo con git init.

      ! [rejected] main -> main (fetch first)

      GitHub tiene commits que tú no tienes (alguien más subió cambios, o editaste algo desde la web). Tráelos primero y vuelve a subir:

      terminal
      git pull
git push
      CONFLICT (content): Merge conflict in archivo

      Tú y otra persona cambiaron las mismas líneas. VS Code marca el conflicto así:

      archivo con conflicto
      <<<<<<< HEAD
<h1>Bienvenidos</h1>       ← tu versión
=======
<h1>Hola a todos</h1>      ← la otra versión
>>>>>>> main
      1. Sobre el conflicto aparecen opciones: Aceptar cambio actual, Aceptar cambio entrante o Aceptar ambos. También puedes editarlo a mano y borrar las marcas.
      2. Guarda el archivo, haz git add archivo y luego git commit.
      remote: Permission denied · 403

      Estás autenticado con otra cuenta, o no eres colaborador del repositorio. Revisa la cuenta en el ícono de Cuentas de VS Code. En Windows, abre Administrador de credenciales → Credenciales de Windows, elimina la de git:https://github.com y vuelve a hacer push para iniciar sesión de nuevo.

      Vocabulario rápido

      repositorio (repo)
      Carpeta de proyecto con historial de Git.
      commit
      Punto guardado del proyecto, con autor, fecha y mensaje.
      staging
      Zona donde eliges qué cambios entran al próximo commit.
      remote / origin
      La copia del repositorio en GitHub y su apodo.
      rama (branch)
      Línea de trabajo paralela; la principal es main.
      merge
      Unir el trabajo de una rama con otra.
      pull request
      Propuesta en GitHub para unir tu rama, con revisión.
      fork
      Copia de un repositorio ajeno dentro de tu cuenta.
      HEAD
      El commit en el que estás parado ahora mismo.

      Práctica final: tu primer repositorio completo

      Hazlo de principio a fin sin mirar arriba. Si te atoras, vuelve al paso indicado.

      1. Crea una carpeta mi-primer-repo con un archivo README.md que diga tu nombre. (paso 10)
      2. Publícala en GitHub como repositorio público. (paso 10)
      3. Agrega un archivo index.html y haz commit con un buen mensaje. (paso 8)
      4. Súbelo con push y compruébalo en la web. (paso 9)
      5. Crea la rama estilos, agrega un style.css, haz commit y súbela. (paso 12)
      6. Abre un pull request de estilos hacia main y únelo. (paso 13)
      7. Vuelve a main en tu PC y haz git pull. Revisa el historial con git log --oneline --graph.
      Tu avance se guarda solo en este navegador.
